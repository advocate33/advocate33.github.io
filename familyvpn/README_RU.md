# Семейный VPN — исходный патч интерфейса WDTT Plus v20

**Статус:** подготовлен исходный код упрощённого интерфейса, но **Android APK не собирался, не подписывался для постоянного распространения и на телефоне не тестировался**. Он не является готовым работающим VPN в отрыве от WDTT Plus и личного VPS.

## Назначение

Семейный форк WDTT Plus v20, GPLv3. Использует штатный туннель WDTT (WireGuard / VK TURN / DTLS), его VPN-службу, импорт профилей, проверку доступа и системное разрешение VPN. Пользователю показываются большая кнопка «Подключить/Отключить», статус транспортных соединений и импорт ссылки/QR только до появления личного профиля. После сохранения профиля элементы импорта, передачи и административных настроек в упрощённом интерфейсе скрываются. Это защита интерфейса от случайной раздачи, а не криптографическая защита. **Контроль количества устройств выполняет wdtt-server v20.** SSH-пароли, клиентские ключи и VK-хеши **не вшиты в исходники**. Приложение получает персональный доступ от владельца сервера.

## Исходный проект

- https://github.com/Ivan4537/WDTT-Plus/releases/tag/v20 — исходная версия
- Ручной серверный установщик: https://github.com/Ivan4537/WDTT-Plus/tree/main/server-installer

КРИТИЧЕСКОЕ УСЛОВИЕ: каждому пользователю выдавать **только сгенерированный индивидуальный пароль клиента**, а не **главный пароль сервера**. В WDTT Plus v20 основной пароль владельца может работать с несколькими устройствами; ограничение устройства относится к персональным паролям.

В сборке меняется `applicationId` на `ru.familyvpn.wdtt` (debug-пакет будет `ru.familyvpn.wdtt.preview`), чтобы не заменить официальный WDTT Plus в телефоне администратора. Для производственной сборки нужен собственный приватный ключ подписи, который следует хранить вне репозитория.

## Состав пакета

- `tools/FamilyHomeScreen.kt` — собственный экран Jetpack Compose с настоящим запуском/остановкой штатной VPN-службы; после сохранения персонального доступа отсутствуют кнопки экспорта/повторного импорта и переход к админ-настройкам.
- `tools/verify_device_binding.py` — проверка, что в сервере v20 сохранилась логика привязки персонального пароля к первому устройству и отказа другому.
- `tools/apply_family_mode.py` — локальный безопасный патчер WDTT Plus v20. Сохраняет копии модифицируемых файлов с расширением `.family-original`.
- `tools/FamilyUpdater.kt` — проверка собственных релизов, уведомление, загрузка APK и запуск системной установки Android.
- `tools/FamilyWifiPolicy.kt` — обязательное выключение семейного туннеля на любом физическом Wi-Fi, без SSID и геолокации.
- `.github/workflows/family-debug.yml` — тестовая сборка с официальных исходников v20 (не проверен запуском).
- `.github/workflows/family-release.yml` — проверка релизов донора раз в неделю, автоматическая подписанная сборка и публикация при успешных проверках (не проверен запуском).
- `config/approved-server-version.txt` — РУЧНО подтверждённая администратором версия уже обновлённого сервера; автоматизация НЕ проверяет ваш VPS и блокирует выпуск при несовпадении.
- `tools/test_patch.py` — автономный тест якорей патча и базовой структуры без компиляции Android.

## Как собрать в GitHub

**Вариант для GitHub Pages CRM пользователя:** разместить эти файлы внутри каталога `familyvpn/` в отдельной ветке `familyvpn-development`. Workflow-файлы разместить в корневой `.github/workflows/` перед активацией. Пока файлы находятся только в отдельной ветке, расписание не запускается. После тестов и принятия изменений в `main` недельная проверка может включиться; CRM и сайт при этом не должны изменяться. Не требуется копировать весь исходный WDTT Plus: GitHub Actions отдельно скачивает исходники релиза донора и применяет семейные изменения. GitHub-публикации APK из приватного репозитория не будут доступны без авторизации, поэтому нужен публичный репозиторий. Исходники распространяем согласно GPLv3.

1. Создайте публичный репозиторий на GitHub и загрузите файлы архива, сохранив структуру `tools/`, `config/`, `.github/workflows/`.
2. Откройте **Actions → FamilyVPN - build UNSIGNED test APK → Run workflow**, проверьте успешность компиляции. APK появится в `FamilyVPN-debug-test-apks`. Это DEBUG, его нельзя раздавать как семейный релиз.
3. Для стабильного канала обновления выполните действия из раздела «Автоматические обновления» ниже; установите выпуск, подписанный ВАШИМ ключом.

**Разработка локально:** можно скопировать каталог `tools` и `config` в корень официальных исходников WDTT Plus v20 и применить патч командой ниже.

При локальной сборке с Android SDK 36, Android NDK и Go 1.26, из корня клона WDTT Plus:

```bash
python3 tools/apply_family_mode.py
./gradlew :app:assembleDebug
```

Перед импортом создайте на **вашем** VPS профиль клиента WDTT Plus v20 и передайте члену семьи его `wdtt://` ссылку или QR. Через приложение допустимы импорт и ручное включение туннеля. Для VK TURN потребуется действующий VK-хеш; он должен присутствовать в профиле либо быть внесён через расширенные настройки.



## Автоматическое выключение на любом Wi-Fi (режим только мобильной сети)

**Семейная сборка должна держать WDTT выключенным при любой подключённой сети Wi-Fi**, включая домашнюю, гостевую и общественную. Это специально сделано, чтобы трафик WDTT через VK TURN не мешал обычным видеозвонкам VK по Wi-Fi. Нельзя ограничиваться только списком «доверенных SSID»: приложение вообще не запрашивает имя Wi-Fi и не требует доступа к геолокации ради этой функции.

- `FamilyWifiPolicy.kt` определяет физическое соединение Wi-Fi через Android `ConnectivityManager` / `NetworkCapabilities.TRANSPORT_WIFI` и `NET_CAPABILITY_NOT_VPN`. Включённый, но **не подключённый** Wi-Fi не запрещает VPN на мобильной сети. Даже Wi-Fi без доступа в интернет считается Wi-Fi и запрещает запуск WDTT.
- Патч `TunnelService.kt` принудительно включает штатную систему «Trusted Wi-Fi» для **всех** Wi-Fi, подменяя реальное имя сети внутренним маркером. При подключении Wi-Fi нативные DTLS-каналы и WireGuard останавливаются, а служба остаётся в режиме ожидания, в том числе когда приложение свёрнуто. Фоновая сеть и восстановление используются из донорского WDTT; это не UI-only решение.
- На экране `FamilyHomeScreen.kt` показывается «Wi-Fi: VPN выключен»; кнопку «Подключить» нельзя использовать на Wi-Fi. Если VPN ещё завершает работу, показывается состояние остановки. Дополнительно старт проверяет тип сети перед вызовом службы. Прямой запуск службы тоже проходит через серверную политику ожидания.
- После отключения Wi-Fi, когда Android подтвердил наличие рабочей мобильной сети, **ранее включённый VPN** автоматически возобновляется штатным механизмом WDTT. Если человек сам нажал «Отключить», автоматического старта не будет. Время восстановления зависит от Android/оператора и не гарантировано.
- Это правило касается **только семейного Android-клиента**. На домашнем Wi-Fi YouTube сможет идти через отдельный VLESS + REALITY на Keenetic. Для звонков VK необходимо настроить на Keenetic прямую маршрутизацию VK-медиасервисов, если выборочная маршрутизация иначе затрагивает их.
- **Нельзя включать для семейного приложения системные опции Android «Всегда включённый VPN» и «Блокировать соединения без VPN»**. Они конфликтуют с намеренным отсутствием VPN на Wi-Fi и могут отключить обычный интернет при ожидании.

### Приёмочные испытания на двух сетях (пока НЕ выполнялись)

1. На LTE/4G/5G нажать «Подключить», проверить активные DTLS-каналы и внешний IP.
2. **Не закрывая приложение**, подключить Wi-Fi: VPN должен отключиться, рабочие каналы перейти в ноль, звонок VK через Wi-Fi должен работать обычным образом. Проверить внешний IP Wi-Fi (для домашнего Keenetic учитывать его выборочные правила).
3. Оставить экран выключенным, повторить переключение мобильная сеть → Wi-Fi; убедиться, что туннель выключается фоновым сервисом.
4. Нажать «Подключить», уже находясь на Wi-Fi: кнопка должна быть недоступна и туннель не должен появиться.
5. Отключить Wi-Fi: если ранее VPN ожидал возвращения мобильной сети, дождаться восстановления сессии; если пользователь вручную выключил VPN, самопроизвольного запуска быть не должно.
6. Проверить плохой Wi-Fi без интернета, одновременный активный LTE и Wi-Fi, переходы Wi-Fi → Wi-Fi и отсутствие доступа к имени SSID / геолокации.
7. Отдельно протестировать повторное подключение после перезапуска службы Android и обновления APK без потери персонального профиля.

**Техническое ограничение:** реагирование на события сети не атомарно. Пока Android доставляет callback и WDTT останавливает транспорт, возможен короткий период передачи пакетов. Нельзя утверждать, что выключение всегда происходит за 0 мс. Если Android принудительно завершит службу, восстановление без пользовательского действия не гарантируется.

## Автоматические обновления семейного приложения

**Текущий статус:** исходный код и GitHub Actions workflow подготовлены; работа на GitHub, подпись APK и фактическое обновление на Android пока НЕ тестировались. Никакой действующий сервер или телефон не изменён.

### Однократная подготовка владельцем

1. Создайте публичный GitHub-репозиторий для семейной сборки и загрузите файлы этого ZIP.
2. На Windows 11 локально создайте ПОСТОЯННЫЙ ключ подписи Android, например установленной Java-командой `keytool -genkeypair -v -keystore familyvpn-release.jks -storetype PKCS12 -alias familyvpn -keyalg RSA -keysize 3072 -validity 3650`. Пароли вводятся интерактивно, без публикации в командной строке. Храните файл и пароли в двух защищённых местах; при их потере обновления поверх прежней установленной сборки будут невозможны.
3. В GitHub **Settings → Secrets and variables → Actions** создайте секреты `FAMILY_KEYSTORE_B64` (base64 содержимого вашего JKS), `FAMILY_STORE_PASSWORD`, `FAMILY_KEY_ALIAS`, `FAMILY_KEY_PASSWORD`. Никогда не помещайте их в код, переписку или логи.
4. Откройте **Actions → FamilyVPN - follow donor and publish signed APK → Run workflow**. Он скачает последний СТАБИЛЬНЫЙ релиз `Ivan4537/WDTT-Plus`, проверит серверную версию, привязку персональных паролей к устройству, применит наш патч, запустит тесты и соберёт подписанный release APK.
5. При успехе GitHub публикует релиз в ВАШЕМ репозитории. Вместе с APK публикуется архив соответствующих исходных текстов для GPLv3. Первый выпуск установите на тестовый Samsung и проверьте связь со своим VPS. Лишь затем раздавайте семье.
6. GitHub Actions требует разрешения `contents: write` для публикации. Workflow использует штатный `GITHUB_TOKEN`, без личного PAT. Для публичного репозитория конечные телефоны читают GitHub releases без авторизации.

### В обычной работе

- GitHub Actions проверяет новый релиз донора **раз в неделю** (расписание приблизительное, возможны задержки со стороны GitHub). Изменение наших файлов в GitHub тоже приводит к новой сборке при следующей проверке. Повторную публикацию одной и той же комбинации версии донора и коммита семейного патча не делает.
- Отдельно от публикации телефон проверяет **наши** Releases: автоматически не чаще раза в неделю; периодическая фоновая проверка через WorkManager назначена каждые 7 дней. Есть кнопка «Проверить обновления», запускающая проверку по запросу. Android может откладывать фоновые проверки из-за энергосбережения.
- После появления нового семейного APK Android показывает уведомление (если разрешены уведомления), а внутри приложения — предложение «Скачать и установить». Пользователь вправе нажать «Позже».
- Пакет скачивается только с нашего фиксированного GitHub-репозитория; проверяются размер, SHA-256 от GitHub и **совпадение подписи APK с уже установленной семейной версией**, затем вызывается системный установщик Android. Разрешение «Установка неизвестных приложений» и подтверждение установки выдаёт пользователь; **тихую установку на обычном Android приложение не делает**. Данные профиля остаются на месте при корректном обновлении того же подписанного `applicationId`.
- APK от официального WDTT Plus не предлагается как обновление семейного клиента. Если GitHub недоступен из-за белых списков, проверка может не сработать до появления связи/туннеля.

### Защита от несовместимых обновлений

- `config/approved-server-version.txt` изначально содержит `20`. Если донор выпускает версию серверной части `21`, автоматическое опубликование **останавливается**: VPS может требовать отдельного обновления. После резервного копирования, тестового обновления WDTT-сервера и подтверждения работоспособности владелец меняет этот файл на `21` в своём репозитории. Это *ручное подтверждение*, не автоматический аудит живого VPS.
- Если исходный код донора изменился так, что наши патчи не совпадают, сборка прекращается, не публикуя потенциально неисправный APK. Потребуется адаптировать патч.
- Релиз сначала создаётся как **черновик**, а публикация происходит только после проверки цифровой подписи APK и соответствия SHA-256 GitHub asset локальному файлу. Если проверка не прошла, черновик остаётся не опубликованным.
- Сохранение одного и того же сертификата подписи и `applicationId` обеспечивает обновление «поверх» старой сборки без повторного ввода конфигурации. Проверяем это фактически на тестовом устройстве, включая VPN-профиль и привязку к устройству.
- Фоновая доставка обновлений НЕ является гарантированно мгновенной. При блокировке GitHub приложение продолжит работать на ранее установленной версии; резервное получение APK администратором предусмотрено вручную.

### Что нужно проверить на реальном устройстве до раздачи семье

1. Сборка и подпись APK, сканирование APK и соответствие package `ru.familyvpn.wdtt`.
2. Старт WDTT со своим VPS и отсутствие экспорта персонального доступа.
3. Проверка доступа с другого телефона: сервер отказывает `DENIED:device_mismatch` после первой регистрации.
4. Wi-Fi отключает туннель и блокирует запуск; LTE возобновляет ранее активный VPN. Новая подписанная сборка с большим `versionCode` выявляется в семейном приложении, скачивается, проверяется и вызывает стандартное окно установки.
5. После обновления сохраняются индивидуальный пароль и регистрация устройства, VPN включается вручную одной кнопкой.
6. При несовместимом сервере или сбое компиляции релиз не публикуется, старый APK не удаляется.

**Важно:** тестовая DEBUG-сборка подписана временным ключом отладки и устанавливается с отдельным идентификатором `ru.familyvpn.wdtt.preview`. Она не обновляется напрямую до подписанной производственной версии `ru.familyvpn.wdtt`; это два разных приложения.

## Запрет передачи доступа другим устройствам

Сервер WDTT Plus v20 в `server.go` уже делает следующее: при первом корректном `GETCONF` с индивидуальным паролем записывает `PasswordEntry.DeviceID`, сохраняет базу и далее отвечает `DENIED:device_mismatch`, если тот же пароль поступает с другим `device_id`. Это **реально серверное** ограничение, действующее даже в другом клиентском приложении. Стандартный `main_password` не защищён этим правилом и никогда не должен попадать в семейный клиент.

**Не следует путать однократную активацию и одноразовый пароль.** Пароль нужен телефону для последующих переподключений. В v20 ссылка сама по себе не становится необратимо непригодной, однако после первой привязки на другом телефоне обычным клиентом не работает. Если ребёнок переслал её ДО первого подключения, другой человек потенциально может активировать доступ первым. Поэтому при выдаче нового доступа администратор должен **сразу выполнить первое подключение на нужном телефоне**. После активации проверить отказ на другом тестовом телефоне.

В нынешнем v20 `device_id` не подтверждается криптографически аппаратным модулем: продвинутый пользователь на модифицированном устройстве может подделать идентификатор и копировать пароль. Для более строгой защиты потребуется дополнительная реализация: ключ в Android Keystore, подтверждение владения приватным ключом для сервера и отдельное одноразовое подтверждение выдачи устройства администратором. **Эта усиленная криптографическая привязка в приложенном пакете НЕ реализована.**

В случае замены/потери телефона администратор отзывает старый доступ или явно выполняет отвязку, а затем выпускает новый пароль; ребёнку административные права не выдаются.

## Проверка

1. Новая сборка не замещает обычный WDTT Plus и имеет отдельное имя «Семейный VPN Тест».
2. Первый запуск может показать системные запросы разрешений и проверку совместимости из оригинального WDTT Plus.
3. Импортируйте тестовую ссылку; проверьте валидность в исходном WDTT Plus и в производном приложении.
4. Сразу активируйте ссылку на предназначенном телефоне. В профиле с индивидуальным паролем сервер запишет `device_id`. Затем проверьте на втором тестовом Android: с теми же данными ожидается отказ `DENIED:device_mismatch` (не публикуя пароль/ссылку). Нажмите «Подключить», предоставьте разрешение VPN, убедитесь, что появились рабочие DTLS-каналы, затем проверьте выходной IP и загрузку YouTube/Telegram.
5. Нажмите «Отключить», убедитесь, что служба остановилась и обычный интернет вернулся.
6. Испытайте переход Wi-Fi ↔ мобильная сеть и период включения белых списков. Проверяйте отзыв персонального доступа на сервере.

## Ограничения и риски

- **Это исходная заготовка для отдельной тестовой Android-сборки, не готовый APK.** Проверку компиляции, поведения и безопасности необходимо выполнить до установки на телефоны семьи.
- Код сохраняет базовый механизм WDTT Plus и потому зависит от его совместимости с сервером v20, инфраструктуры VK TURN и политики мобильного оператора.
- У семейной сборки скрыты расширенные/административные экраны при обычном запуске. Исходный код этих функций всё ещё присутствует внутри производной сборки; это не считается границей безопасности.
- Для семейного приложения исключён запуск локальных SOCKS/HTTP-прокси по штатной кнопке. Это не исключает нетипичное перенаправление трафика через root-доступ или другое ПО на телефоне.
- QR/ссылка для первоначального импорта содержит пароль. Передавайте её напрямую получателю, не в открытой группе. После первоначальной настройки скрыты кнопки импорта и экспорта профиля, но извлечение секретов на взломанном устройстве нельзя полностью исключить.
- Не пересылайте приватные ключи, ссылки доступа или VK-хеши в открытых чатах. Логи перед публикацией обезличивайте.
- Для постоянного распространения нужен собственный стабильный ключ подписи и проверенная автоматическая сборка; тестовые debug APK для этого не подходят. Канал обновлений подготовлен в исходниках, но ещё не испытан.
- Из-за наследования манифеста WDTT Plus производная сборка пока сохраняет разрешения оригинального приложения, включая административные функции. Перед постоянной выдачей семье необходим аудит разрешений и удаление ненужных привилегий.
- В соответствии с GPLv3 при распространении производной программы необходимо соблюдать условия лицензии и предоставить соответствующие исходные тексты.

## Проверка VPS и Keenetic

Entware и Xray/sing-box на Keenetic ранее были установлены, но сейчас отключены. Не менять маршрутизацию роутера до настройки и проверки отдельного VLESS+REALITY сервиса на VPS. У WDTT обычно внешний порт 56000/UDP; VLESS+REALITY может использовать отдельный 443/TCP. Системные firewall/SSH правила менять только с резервным консольным доступом.


## Особенности общего репозитория CRM и VPN

- Для исходников используется отдельный каталог `familyvpn/`. Рабочие файлы CRM (`index.html`, `sw.js`, `next/`, `next-gpt/`, `dist/`) не изменяются.
- GitHub Actions должен лежать в КОРНЕ репозитория (`.github/workflows/family-release.yml`), а пути в сценарии указывают на `family/familyvpn/tools` и `family/familyvpn/config`.
- Релизы фильтруются строго по префиксу тега `family-vN-SHA` и имени APK `FamilyVPN-<code>.apk` из `GET /releases?per_page=50`, чтобы не принять релиз CRM за релиз VPN. При более чем 50 релизах в списке требуется пагинация.
- Обновляющее приложение сравнивает свой versionCode и сертификат APK; выпуск CRM не должен быть помечен как обновление VPN.
- Не публикуйте исполняемые APK в корневой папке GitHub Pages, чтобы не раздавать их со страниц CRM. Используйте изолированные GitHub Releases.
- `schedule` на ветке `familyvpn-development` **не выполняется**, пока workflow не находится в default-ветке `main`. Не соединяйте ветку с `main`, пока APK не проверен и не настроены секреты подписи.
- Частота: GitHub `cron: 17 4 * * 1` (каждый понедельник 04:17 UTC), телефон: WorkManager каждые 7 дней приблизительно и ручная кнопка.
