# Next GPT

Отдельный вариант CRM для разработки и сравнения с next. Ветка: chatgpt-dev. Первая версия: next-gpt-1.

## Основа

Скопирован актуальный next из коммита a02ded825b8f837472082fa165f1f58692351cca (02.10.2026, 09:47 МСК). Исходные next/index.html, корневая CRM и main не изменялись при создании этого каталога. Дизайн пока соответствует этой версии next; предложенные визуальные макеты будут внедряться отдельными изменениями.

## Изоляция данных

- Основная база: crm_advocate_next_gpt.
- Служебные базы: crm_advocate_local_next_gpt и crm_fsync_next_gpt.
- Настройки localStorage/sessionStorage: префикс next-gpt:.
- Неизвестные имена IndexedDB запрещены. Операция Storage.clear ограничена своим префиксом.
- Service Worker размещён рядом с index.html, область ./, кэш crm-next-gpt-v1. Кэши старой CRM и next не удаляет.
- Данные и секреты исходных приложений автоматически не читаются и не копируются.
- Сервер: только ping, dbver, dbget, blobget, bloblist, eventsget. Запись базы, вложений и событий запрещена.
- Коллектор: только status. linksput, collect, collectone и bridgecheck отключены, чтобы тестирование не меняло серверное состояние.
- Автоприменение событий суда и смена статуса прошедших заседаний при запуске отключены. Ручные действия меняют только тестовую копию.

Разделение внутри одного домена защищает от штатных пересечений приложения, но не является отдельной границей безопасности браузера. Не очищайте все данные сайта: такая браузерная операция удаляет данные всех вариантов.

## Как сравнивать

1. Сначала сохранить резервную копию в основной CRM.
2. Открыть исходный next и Next GPT в отдельных вкладках.
3. Next GPT изначально пустой. Через «О тестировании» → «Загрузить копию с сервера» самостоятельно ввести URL, секрет и пароль, проверить связь, загрузить снимок. Секреты не передавать в чат и не добавлять в GitHub.
4. Каждую отличающуюся зашифрованную копию Next GPT сохраняет в собственной служебной базе ДО слияния. Ключ — SHA-256 содержимого; существующий снимок не перезаписывается. Ошибка архивирования прерывает импорт.
5. Кнопка «Скачать исходный снимок» экспортирует зашифрованный снимок сервера в формате next-gpt-encrypted-baseline-1. Это архив исходника, а не резервная копия текущих тестовых правок. Для расшифровки нужен пароль сервера; интерфейс восстановления такого архива пока не реализован.
6. Проверять одинаковые дела, суммы и документы. Создавать и редактировать тестовые записи только в Next GPT. Проверить сохранение после перезапуска и неизменность оригинала.
7. Повторная загрузка с сервера выполняет слияние, НЕ сброс тестовой базы. Не рассчитывать на неё как на откат экспериментов.

## Запуск и публикация

index.html — самостоятельное приложение. Для корректной проверки IndexedDB, Web Crypto и офлайн-работы использовать HTTPS либо локальный сервер localhost; поведение file:// зависит от браузера. Например, открыть терминал в папке next-gpt, запустить python -m http.server 8000 и открыть localhost:8000.

Файлы находятся в chatgpt-dev. Наличие каталога в этой ветке само по себе не публикует новый адрес GitHub Pages. Не переключать источник Pages на chatgpt-dev: это заменит опубликованный сайт содержимым другой ветки. Публикацию отдельного каталога выполнять только после согласования ограничения «main не трогать».

## Проверки первой версии

Пройдены локальные изолированные проверки: синтаксис полного JavaScript приложения; раздельная запись и очистка local/sessionStorage; сохранность значений старой CRM и next; запрет открытия/удаления чужой IndexedDB; блокировка серверных команд записи; Service Worker не удаляет чужие кэши и не перехватывает страницы вне своей стартовой страницы.

Это проверки кода в моделируемом окружении, не полная приёмка браузера. Реальная база пользователя, его сервер и авторизация при создании версии не использовались. После публикации необходимы проверки запуска, перезагрузки, загрузки копии, неизменности оригинала и работы на телефоне.

## Правила дальнейшей разработки

Изменять только next-gpt/ в chatgpt-dev. Не объединять всю ветку с main: в ней есть более ранний отдельный коммит next. Перед каждым выпуском проверять изоляцию; сохранять совместимость загруженных данных. Изменение пространств имён, серверных разрешений и миграций — отдельная проверяемая задача. Не добавлять реальные базы, секреты или архивы доверителей в репозиторий.

Порядок работ: закончить приёмку изоляции в браузере → перенести согласованный дизайн → исправлять и переносить функции по аудиту → сравнивать с исходным next на одинаковых копиях данных.
